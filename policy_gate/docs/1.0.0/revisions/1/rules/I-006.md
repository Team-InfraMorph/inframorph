# I-006 · 일반 설정과 비밀정보 분리

## 목적과 검사

지원 설정만 사용하고 비밀정보 이름을 덮어쓰지 않아야 합니다.

## 적용 조건

단계 intent · reviewed-node22 · rule('I-006')

## 정상 사례

PORT=3000처럼 지원 설정을 사용하고 DATABASE_URL은 비밀정보로 분리합니다.

## 위반·미지원 사례

NODE_OPTIONS=--inspect 같은 허용되지 않은 값이나 비밀정보와 같은 설정 키는 차단합니다. CUSTOM처럼 지원하지 않는 키는 미지원입니다.

## 수정 방법

설정 이름·값과 비밀정보 충돌을 확인하세요.

## 한계

비밀값 자체의 유효성은 검사하지 않고 이름 충돌과 허용 설정을 검사합니다.
