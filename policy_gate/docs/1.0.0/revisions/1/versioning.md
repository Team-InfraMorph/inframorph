# 버전 관리와 출시 절차

## 공개 계약

정책의 공개 계약은 지원 입력, 적용 조건, 판정 의미, 필수 규칙과 결과 형식입니다. 정식 정책은 inframorph-policy/1.0.0에서 시작합니다.

## 버전 증가

PATCH는 문서화된 계약을 잘못 실행한 버그 수정, MINOR는 기존 계약을 유지하는 기능 추가, MAJOR는 지원 제거 또는 기존 입력에 대한 새로운 차단 조건입니다. 패치 보안 수정도 재검사가 필요할 수 있습니다.

## 문서 revision

설명 정정은 문서 revision으로 남깁니다. 정책 규칙 묶음과 구현은 출시 후 덮어쓰지 않습니다. 문서 revision도 이전 자료를 보존합니다.

## Git 관리

규칙 변경 → 문서와 영향 명세 → 정상/위반 회귀 테스트 → CI → PR 검토 → policy/v1.0.0 태그 → 서버 배포 순서입니다. 이 개발 작업에서는 커밋·push·PR·태그를 만들지 않습니다.

## 활성 정책

문서 버전 선택은 조회입니다. 활성 정책은 검토한 서버 배포물로 변경합니다. UI에서 과거 검사기로 전환하지 않습니다. 출시 상태와 활성 여부는 서로 다릅니다.


## 문서 revision과 고정 링크

문서는 docs/버전/revisions/정수/에 저장합니다. 정정은 새 revision 디렉터리를 추가하고 이전 파일을 유지합니다. API의 revision 인자와 화면 URL의 revision 인자로 이전 설명을 조회합니다. 출시 manifest의 document_revision은 최초 묶음을 가리키며 이후 정정은 별도의 문서 폴더로 보존합니다.

## 출시 점검

개발 중에는 frozen_hashes가 비어 있습니다. 출시 전에 규칙·구현·문서 해시, 구현 commit, PR, policy/v버전 태그, redteam revision을 검토하여 고정해야 합니다. 이번 작업은 출시·태그를 생성하지 않습니다. CI는 기존 출시 manifest와 문서 revision을 수정하거나 구현 변경에 변경 명세가 없는 경우 실패합니다.
