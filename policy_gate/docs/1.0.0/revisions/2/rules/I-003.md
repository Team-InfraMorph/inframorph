# I-003 · DB 종류와 근거 일치

정책 1.0.0 · 규칙 revision 1 · 문서 revision 2

## 목적 {#purpose}

AI의 DB 종류·존재 주장과 실제 Prisma datasource를 대조합니다. 파일 존재만 통과한 잘못된 DB 분석을 막습니다.

## 입력과 적용 조건 {#inputs}

검증된 Intent의 relational_db 항목, prisma/schema.prisma 원본 바이트와 인용 줄을 사용합니다. I-001과 I-006 통과 후 실행합니다.

## 처리 과정 {#procedure}

1. 스키마가 있으면 지원 토큰 파서로 하나의 datasource와 sqlite/postgresql provider 및 datasource 범위를 찾습니다.
2. DB 분석이 비어 있으면 요구 누락으로 차단합니다. DB 항목마다 engine이 관찰한 provider와 같은지 확인합니다.
3. 각 DB 항목의 인용 중 적어도 하나가 해당 스키마 datasource 범위와 겹치는지 검사합니다.
4. 스키마가 없는데 DB를 주장하면 차단합니다. 둘 다 없으면 이 규칙은 PASS이며 DB 존재를 새로 증명한 것은 아닙니다.

## 판정 기준과 사유 {#decisions}

| 사유 코드 | 현재 판정 | 발생 조건 | 확인과 조치 |
|---|---|---|---|
| db_requirement_missing | BLOCK | 스키마는 있으나 DB 요구가 없음 | 분석에서 빠진 DB 요구와 관련 근거를 복원합니다. |
| db_provider_mismatch | BLOCK | engine과 소스 provider가 다름 | 원본 설정을 확인하고 잘못된 분석을 재생성합니다. 실제 DB 변경이라면 별도 앱 변경·마이그레이션 검토가 필요합니다. |
| db_evidence_unrelated | BLOCK | 인용이 datasource와 겹치지 않음 | datasource를 뒷받침하는 실제 줄을 찾아 제시합니다. |
| db_schema_missing | BLOCK | DB를 주장하나 고정 경로 스키마가 없음 | 다른 ORM·경로라면 지원 범위를 검토합니다. 임의 스키마를 만들어 통과시키지 않습니다. |
| prisma_structure_unsupported | UNSUPPORTED | 파서의 지원 구조 밖 | 지원 구문과 실제 구조를 확인하고 지원 확대 검토 대상으로 남깁니다. |

위 조건을 모두 만족하면 해당 규칙 PASS입니다. 전체 배포 성공을 뜻하지 않습니다. 앞선 규칙에서 중단되면 NOT_RUN이며, 적용 제외는 명시된 조건에서만 NOT_APPLICABLE로 남습니다. [공통 오류 분류](../results.md#classification)도 확인하세요.

## 근거 읽기 {#evidence}

path, observed(provider), claimed(engine 목록)를 기록합니다. 전체 스키마나 DB 접속 정보는 기록하지 않습니다. 파싱 전에 실패하면 관찰값도 없을 수 있습니다.

## 해결과 재검증 {#remedy}

1. 스키마와 분석의 source_revision을 맞춰 비교합니다.
2. 소스가 맞으면 분석을 수정하고, 소스 변경이 필요하면 새 commit의 일반 배포를 생성합니다.
3. 새 분석의 I-001·I-003 및 뒤의 설계 검사를 확인합니다. 기존 자료 재검사는 잘못된 분석을 자동 수정하지 않습니다.

[실패에서 다시 시작하는 방법](../troubleshooting.md#restart)을 참고하세요. 보존 자료 재검사는 원본 입력을 고치거나 새 소스를 가져오지 않습니다.

## 검증 사례 {#cases}

| 종류 | 입력 또는 상황 | 기대 결과 |
|---|---|---|
| 정상 | 원본 sqlite·분석 sqlite·datasource 인용 | PASS |
| 위반 | 원본 sqlite·분석 postgresql 또는 DB 항목 삭제 | BLOCK |
| 경계 | 유효한 파일 줄이지만 모델 영역만 인용 | I-001 통과 후 I-003 BLOCK |
| 오류/미지원 | 지원 밖 datasource 구조 | UNSUPPORTED; 이후 저장·worker NOT_RUN |

위 표는 동작 설명입니다. 자동 재현한 범위와 테스트 연결은 아래 근거 및 [검증 사례집](../cases.md#reproduced)에서 구분합니다.

## 한계와 관련 검사 {#limits}

고정 경로의 제한된 Prisma 구조만 검사합니다. 실제 DB 접속, 기존 데이터 마이그레이션, SQL 의미 동등성은 검사하지 않습니다. G-002가 먼저 정확한 demo 상태를 요구하여 실제 경로에서는 intent_source_mismatch로 먼저 멈출 수 있습니다.
