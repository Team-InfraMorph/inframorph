# P-002 · diff와 결과물 일치

정책 1.0.0 · 규칙 revision 1 · 문서 revision 2

## 목적 {#purpose}

제출된 diff를 원본에 적용한 실제 결과가 제출된 패치 소스와 같은지 확인합니다.

## 입력과 적용 조건 {#inputs}

P-001에서 확인한 원본 파일 집합, patch.diff, patched 파일 집합. 해시가 모두 맞아도 독립적으로 적용 결과를 비교합니다.

## 처리 과정 {#procedure}

1. 임시 폴더에 원본을 쓰고 빈 Git 저장소를 초기화합니다.
2. diff가 비어 있지 않으면 git apply를 수행합니다. 앱 코드는 실행하지 않습니다.
3. 적용 결과를 다시 안전하게 읽어 파일 집합과 바이트를 patched와 비교합니다.
4. 임시 자료는 검사 종료 시 정리합니다. 실제 원본 레포를 수정하지 않습니다.

## 판정 기준과 사유 {#decisions}

| 사유 코드 | 현재 판정 | 발생 조건 | 확인과 조치 |
|---|---|---|---|
| diff_apply_failed | BLOCK | diff가 원본에 적용되지 않음 | 같은 원본으로 패치를 다시 생성합니다. |
| diff_source_mismatch | BLOCK | 적용 결과와 제출 소스가 다름 | diff·source를 같은 변환 결과에서 생성합니다. |
| diff_checker_unavailable | ERROR | Git 실행 또는 제한 시간 문제 | Git 설치·권한·실행 환경을 복구합니다. |

위 조건을 모두 만족하면 해당 규칙 PASS입니다. 전체 배포 성공을 뜻하지 않습니다. 앞선 규칙에서 중단되면 NOT_RUN이며, 적용 제외는 명시된 조건에서만 NOT_APPLICABLE로 남습니다. [공통 오류 분류](../results.md#classification)도 확인하세요.

## 근거 읽기 {#evidence}

input_digest에는 diff의 SHA-256을 기록합니다. 전체 적용 로그는 원문으로 저장하지 않습니다.

## 해결과 재검증 {#remedy}

1. P-001 통과 여부와 원본 commit을 확인합니다.
2. 명세만 수정하지 말고 diff와 패치 소스를 함께 재생성합니다.
3. P-002 이후 변환 규칙과 빌드 직전 재검사를 확인합니다.

[실패에서 다시 시작하는 방법](../troubleshooting.md#restart)을 참고하세요. 보존 자료 재검사는 원본 입력을 고치거나 새 소스를 가져오지 않습니다.

## 검증 사례 {#cases}

| 종류 | 입력 또는 상황 | 기대 결과 |
|---|---|---|
| 정상 | diff 적용 결과가 source와 동일 | PASS |
| 위반 | diff와 source를 각자 바꾸어 해시만 일치 | BLOCK |
| 경계 | 빈 diff·원본과 같은 source | PASS |
| 오류 | Git 실행 실패 | ERROR |

위 표는 동작 설명입니다. 자동 재현한 범위와 테스트 연결은 아래 근거 및 [검증 사례집](../cases.md#reproduced)에서 구분합니다.

## 한계와 관련 검사 {#limits}

diff의 재현성을 증명하며 변환의 사업적 안전성을 증명하지 않습니다. 읽기·경로 공통 검사 오류도 적용 결과 읽기 중 발생할 수 있습니다.
