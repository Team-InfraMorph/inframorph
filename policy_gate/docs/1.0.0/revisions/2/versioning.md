# 정책 버전과 문서 변경 관리

## 무엇을 따로 관리하나요 {#versions}

| 식별값 | 의미 | 이번 작업 |
|---|---|---|
| 정책 버전 | 지원 입력·판정 조건·결과 계약 | 1.0.0 유지 |
| 규칙 revision | 해당 규칙 조건의 이력 | 1 유지 |
| 문서 revision | 같은 정책의 설명 정정·보완 | 1 보존, 2 추가 |
| 구현 식별값 | 실행 코드의 내용 | 변경 없음 |

문서 상세화가 새 정책을 출시한 것은 아닙니다. 문서 조회 버전 선택도 활성 정책 변경이 아닙니다.

## 향후 판정이 바뀌는 경우 {#behavior-change}

문서화한 계약의 실행 오류 수정은 PATCH, 기존 계약을 유지한 선택 기능은 MINOR, 기존 지원 입력의 새로운 차단 조건·지원 제거는 MAJOR 원칙으로 검토합니다. 보안 오류를 고친 PATCH도 재검사가 필요할 수 있으므로 숫자만으로 조치를 결정하지 않습니다.

현재 상태 → 재현 사례 → 새 조건 → 영향 대상 → 필요한 재검사·검토·재배포 → 회귀 근거를 함께 검토합니다. 문서 담당자가 실제 조건 변경을 설명 정정으로 처리해서는 안 됩니다.

## 보존과 기본 문서 {#revisions}

과거 검사에는 당시 문서 revision을 사용합니다. 새 설명은 별도 revision으로 보존하고 기존 URL을 유지합니다. 현재 개발 manifest의 document_revision만 2로 지정합니다. 기존 document_revisions 필드는 초기 묶음 정보이며 실제 조회 가능한 revision 목록은 API가 보존 폴더에서 제공합니다. 판정 해시에 포함되는 기존 필드를 문서 작업으로 함께 변경하지 않습니다.

출시 이후에는 고정 manifest를 덮어쓰지 않는 원칙을 유지합니다. 출시 버전의 기본 문서 포인터 변경 절차 확장은 이번 작업에 포함하지 않습니다. 현재 작업을 출시 이력으로 표시하지 않습니다.
