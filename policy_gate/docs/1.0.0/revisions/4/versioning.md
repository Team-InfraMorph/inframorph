# 정책 버전과 문서 변경 관리

## 무엇을 따로 관리하나요 {#versions}

| 식별값 | 의미 | 이번 작업 |
|---|---|---|
| 정책 버전 | 지원 입력·판정 조건·결과 계약 | 1.0.0 유지 |
| 규칙 revision | 해당 규칙 조건의 이력 | 1 유지 |
| 문서 revision | 같은 정책의 설명 정정·보완 | 1·2·3 보존, 4 추가 |
| 구현 식별값 | 실행 코드의 내용 | 현재 138e6ca 기준; 이번 문서 보완으로 변경 없음 |

문서 상세화가 새 정책을 출시한 것은 아닙니다. 문서 조회 버전 선택도 활성 정책 변경이 아닙니다.

## 향후 판정이 바뀌는 경우 {#behavior-change}

문서화한 계약의 실행 오류 수정은 PATCH, 기존 계약을 유지한 선택 기능은 MINOR, 기존 지원 입력의 새로운 차단 조건·지원 제거는 MAJOR 원칙으로 검토합니다. 보안 오류를 고친 PATCH도 재검사가 필요할 수 있으므로 숫자만으로 조치를 결정하지 않습니다.

현재 상태 → 재현 사례 → 새 조건 → 영향 대상 → 필요한 재검사·검토·재배포 → 회귀 근거를 함께 검토합니다. 문서 담당자가 실제 조건 변경을 설명 정정으로 처리해서는 안 됩니다.

## 보존과 기본 문서 {#revisions}

과거 검사에는 당시 문서 revision을 사용합니다. 새 설명은 별도 revision으로 보존하고 기존 URL을 유지합니다. 현재 manifest의 document_revision은 4입니다. 기존 document_revisions 필드는 초기 묶음 정보이며 실제 조회 가능한 revision 목록은 API가 보존 폴더에서 제공합니다. 판정 해시에 포함되는 기존 필드를 문서 작업으로 함께 변경하지 않습니다.

출시 이후에는 고정 manifest를 덮어쓰지 않는 원칙을 유지합니다. 출시 버전의 기본 문서 포인터 변경 절차 확장은 이 문서 보완에는 포함하지 않습니다. 이 기준선 고정을 원격 출시 이력으로 표시하지 않습니다.

## 1.0.0 기준선 {#baseline}

정책 1.0.0은 규칙 18개·규칙 revision 1의 판정 조건을 유지합니다. main fa84467 통합 구현은 138e6ca, 문서 revision 3을 고정한 로컬 commit은 544ae0c입니다. revision 4는 그 위에서 네 가지 설명을 보완한 문서입니다. 출시 태그나 원격 PR 기록으로 표시하지 않습니다.

| 보호 장치 | 실제 확인 범위 | 확인하지 않는 것 |
|---|---|---|
| Git commit | 그 commit에 포함된 저장소 파일의 이력·차이 | commit 자체가 테스트 성공이나 변경 승인 증거는 아님 |
| 정책 구현 식별값 | catalog의 IMPLEMENTATION 목록, schemas·code_patch/templates 아래 .py/.js/.json 내용 | 저장소의 모든 실행 파일을 자동 포함하지 않음 |
| 규칙·정책 식별값 | 규칙 카탈로그와 문서 포인터 등 제외 항목을 뺀 manifest, 위 구현 식별값 | 문서 수정과 모든 배포 동작의 변화를 같은 것으로 판단하지 않음 |
| 문서 기준선 파일 | revision 1·2·3의 파일 목록과 각 바이트 해시, 활성 1.0.0의 정책·규칙·구현 식별값 | revision 4 파일은 기존 고정 목록에 없음. 이전 기준선 파일을 수정해 포함한 것으로 만들지 않음 |
| Git 기준 비교를 포함한 카탈로그 검사 | 비교 대상 commit의 기준선 파일이 수정·삭제되지 않았는지 | 비교 기준 없이 실행하면 기준선 파일 자체의 과거 내용 비교는 하지 않음 |
| 문서 회귀 검사 | revision 4의 링크·계약 예시·실제 기록 재현, revision 1·2·3 보존, 판정 식별값 불변 | 문장의 의미 전체·새 호출 경로 전체가 자동 검증되는 것은 아님 |

현재 구현 해시에는 Gate·규칙·기록·정책 API·Local/AWS Adapter·Builder 등의 명시된 파일이 포함됩니다. `control_plane/runtime.py`, `control_plane/orchestrator.py`, `control_plane/onprem_deploy.py`, `code_patch/runner.py`는 이 명시 목록과 추가 폴더 범위에 없습니다. 이 파일의 변경이 정책 해시를 반드시 바꾼다고 가정하지 말고 Git 차이와 해당 실행 회귀 결과를 함께 확인합니다. 전체 배포 제어 흐름이 같은 해시 아래 불변이라고 보장하지 않습니다.

`policy_gate/baselines/1.0.0.json`과 revision 1·2·3은 그대로 보존합니다. revision 4의 review.json은 이전 revision의 해시와 작성 기준을 기록합니다. 이번 revision 3→4 설명 보완 전후에는 정책·규칙·구현 해시가 같고 문서 해시만 달라집니다. 기준선 검사의 범위와 판정 해시 계산 방식은 변경하지 않았습니다. 이는 저장소 검증이며 외부 감사 시스템 수준의 위변조 방지 보장은 아닙니다.
