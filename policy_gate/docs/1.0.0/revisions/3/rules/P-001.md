# P-001 · 패치 묶음과 변경 범위

정책 1.0.0 · 규칙 revision 1 · 문서 revision 3

## 목적 {#purpose}

패치 묶음의 출처·해시·변경 파일 선언을 독립적으로 확인합니다. 모델의 승인 표시만 믿지 않습니다.

## 입력과 적용 조건 {#inputs}

원본 snapshot, bundle의 manifest.json·patch.diff·source/, Plan의 commit·target. 패치 단계의 첫 규칙입니다.

## 처리 과정 {#procedure}

1. Plan을 파싱하고 원본·bundle을 안전한 파일 읽기 제한으로 읽습니다.
2. manifest와 diff 존재, source/ 외 추가 파일 금지, manifest 버전 1.0.0과 패치 소스의 비밀 경로 제외를 검사합니다.
3. manifest의 commit·target을 Plan과 비교하고 requires_policy_gate=true를 요구합니다. 이 플래그 자체가 승인 증거는 아닙니다.
4. 원본·패치 소스·diff의 해시를 직접 계산하여 manifest와 대조합니다.
5. 실제 변경 경로가 기본 허용 5개 파일 이내인지, 삭제가 없는지 확인합니다. 변경 목록의 순서·action·전후 해시·status까지 실제 값과 비교합니다.

## 판정 기준과 사유 {#decisions}

| 사유 코드 | 현재 판정 | 발생 조건 | 확인과 조치 |
|---|---|---|---|
| bundle_incomplete / bundle_extra_file | BLOCK | 필수 파일 누락 또는 추가 자료 | 동일 소스로 정식 bundle을 다시 생성합니다. |
| manifest_invalid / manifest_version_unsupported | BLOCK 또는 UNSUPPORTED | manifest 형식 또는 버전 미지원 | 지원 manifest 계약을 확인합니다. |
| sensitive_source_path | BLOCK | 패치 소스에 금지 경로 또는 비어 있는 소스 | 비밀 자료를 제거하고 전체 묶음을 재생성합니다. |
| revision_or_target_mismatch / manifest_gate_flag_missing | BLOCK | 다른 소스·대상 또는 필수 플래그 누락 | 동일 commit·대상의 bundle을 사용합니다. |
| artifact_digest_mismatch | BLOCK | 내용과 선언 해시 불일치 | 생성 이후 변조·전달 오류를 확인합니다. 해시만 고쳐 통과시키지 않습니다. |
| patch_allowlist_violation / deletion_forbidden | BLOCK | 허용 밖 변경 또는 삭제 | 변경 범위를 검토하고 생성기 출력을 수정합니다. |
| change_manifest_mismatch / patch_status_mismatch | BLOCK | 변경 목록·상태가 실제 내용과 다름 | diff·소스·manifest를 함께 다시 생성합니다. |

위 조건을 모두 만족하면 해당 규칙 PASS입니다. 전체 배포 성공을 뜻하지 않습니다. 앞선 규칙에서 중단되면 NOT_RUN이며, 적용 제외는 명시된 조건에서만 NOT_APPLICABLE로 남습니다. [공통 오류 분류](../results.md#classification)도 확인하세요.

## 근거 읽기 {#evidence}

changed_paths·source_revision·target·input_digest는 해시 검사 이후에 채워집니다. 더 이른 실패에서는 비어 있을 수 있습니다. 읽기 제한 오류도 이 규칙에 귀속됩니다.

## 해결과 재검증 {#remedy}

1. 원본·대상·전달 경로와 bundle 생성 시점을 확인합니다.
2. 현재 앱 소스 변경과 배포용 패치를 구분해 수정합니다.
3. P-001부터 후속 패치 규칙 전체를 실행합니다. 해시 일치만으로 코드 안전성을 승인하지 않습니다.

[실패에서 다시 시작하는 방법](../troubleshooting.md#restart)을 참고하세요. 보존 자료 재검사는 원본 입력을 고치거나 새 소스를 가져오지 않습니다.

## 검증 사례 {#cases}

| 종류 | 입력 또는 상황 | 기대 결과 |
|---|---|---|
| 정상 | 정확한 원본·diff·source·manifest | PASS |
| 위반 | source 변경 후 manifest 유지 | BLOCK · artifact_digest_mismatch |
| 경계 | 원본과 같은 bundle·빈 diff | unchanged로 일치해야 PASS |
| 오류 | 소스 읽기 또는 공통 스키마 실패 | 해당 고정 코드로 종료; 후속 NOT_RUN |

위 표는 동작 설명입니다. 자동 재현한 범위와 테스트 연결은 아래 근거 및 [검증 사례집](../cases.md#reproduced)에서 구분합니다.

## 한계와 관련 검사 {#limits}

허용 경로는 prisma/schema.prisma, src/images.js, src/storage.js, package.json, package-lock.json입니다. 호스트 테스트가 허용 목록을 별도 전달할 수 있으나 사용자 bundle에서 허용 범위를 정하지 않습니다.
