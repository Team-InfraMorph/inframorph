# 정책 버전과 문서 변경 관리

## 무엇을 따로 관리하나요 {#versions}

| 식별값 | 의미 | 이번 작업 |
|---|---|---|
| 정책 버전 | 지원 입력·판정 조건·결과 계약 | 1.0.0 유지 |
| 규칙 revision | 해당 규칙 조건의 이력 | 1 유지 |
| 문서 revision | 같은 정책의 설명 정정·보완 | 1·2 보존, 3 추가 |
| 구현 식별값 | 실행 코드의 내용 | 현재 138e6ca 기준; 이번 문서 보완으로 변경 없음 |

문서 상세화가 새 정책을 출시한 것은 아닙니다. 문서 조회 버전 선택도 활성 정책 변경이 아닙니다.

## 향후 판정이 바뀌는 경우 {#behavior-change}

문서화한 계약의 실행 오류 수정은 PATCH, 기존 계약을 유지한 선택 기능은 MINOR, 기존 지원 입력의 새로운 차단 조건·지원 제거는 MAJOR 원칙으로 검토합니다. 보안 오류를 고친 PATCH도 재검사가 필요할 수 있으므로 숫자만으로 조치를 결정하지 않습니다.

현재 상태 → 재현 사례 → 새 조건 → 영향 대상 → 필요한 재검사·검토·재배포 → 회귀 근거를 함께 검토합니다. 문서 담당자가 실제 조건 변경을 설명 정정으로 처리해서는 안 됩니다.

## 보존과 기본 문서 {#revisions}

과거 검사에는 당시 문서 revision을 사용합니다. 새 설명은 별도 revision으로 보존하고 기존 URL을 유지합니다. 현재 manifest의 document_revision은 3입니다. 기존 document_revisions 필드는 초기 묶음 정보이며 실제 조회 가능한 revision 목록은 API가 보존 폴더에서 제공합니다. 판정 해시에 포함되는 기존 필드를 문서 작업으로 함께 변경하지 않습니다.

출시 이후에는 고정 manifest를 덮어쓰지 않는 원칙을 유지합니다. 출시 버전의 기본 문서 포인터 변경 절차 확장은 이 문서 보완에는 포함하지 않습니다. 이 기준선 고정을 원격 출시 이력으로 표시하지 않습니다.

## 1.0.0 기준선 {#baseline}

문서 revision 3은 규칙 18개, 규칙 revision 1, 현재 판정 조건을 설명합니다. main fa84467을 통합한 구현 commit 138e6ca를 기준으로 하며 문서 작업은 그 위의 로컬 변경입니다. 출시 태그나 원격 PR을 생성한 기록은 없습니다.

`policy_gate/baselines/1.0.0.json`에 정책·규칙·구현 식별값과 문서 revision 1·2·3의 파일 해시를 보존합니다. 카탈로그 검사는 고정된 문서의 변경·삭제·추가와 활성 1.0.0 판정 식별값의 변화를 확인합니다. 기준 파일 자체의 수정·삭제도 Git 비교 기준이 있으면 검사합니다. 이는 저장소 검증이며 외부 감사 시스템 수준의 위변조 방지 보장은 아닙니다.

문서 revision 2 작성 당시의 review.json은 당시 자료로 남습니다. main 통합 전의 구현 해시와 현재 구현 해시는 다릅니다. 이번 revision 2→3 설명 보완 전후의 정책·규칙·구현 해시는 동일하며 문서 해시만 달라집니다.
