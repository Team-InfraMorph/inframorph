# P-006 · JavaScript 실행 구문

정책 1.0.0

## 목적 {#purpose}

패치 소스의 JS를 구문 분석하여 알려진 동적 실행·프로세스 호출 구문과 문법 오류를 거부합니다.

## 입력과 적용 조건 {#inputs}

패치 소스 전체의 .js/.cjs/.mjs. 변경한 파일만 검사하는 것이 아닙니다.

## 처리 과정 {#procedure}

1. Node의 호스트 소유 Acorn 파서를 메모리·시간 제한으로 실행합니다. 사용자 JS는 실행하지 않습니다.
2. ECMAScript 2022 구문을 파싱합니다. .mjs는 module, 나머지는 script 모드입니다.
3. eval·Function 식별자 참조, 일부 전역 객체 호출, 정적인 child_process import/require를 찾으면 차단합니다.
4. 파일별 첫 파싱 오류 또는 금지 구문에서 종료합니다.

## 판정 기준과 사유 {#decisions}

| 사유 코드 | 현재 판정 | 발생 조건 | 확인과 조치 |
|---|---|---|---|
| javascript_syntax_invalid | BLOCK | 지원 파서에서 문법 오류 | 문법 또는 지원 언어 범위를 확인합니다. |
| forbidden_code_pattern | BLOCK | 금지 AST 참조 발견 | 해당 실행 동작을 제거하거나 지원 검토로 분리합니다. |
| javascript_parser_unavailable | ERROR | 파서 실행·응답 처리 실패 | Node·파서·실행 환경을 복구합니다. |

위 조건을 모두 만족하면 해당 규칙 PASS입니다. 전체 배포 성공을 뜻하지 않습니다. 앞선 규칙에서 중단되면 NOT_RUN이며, 적용 제외는 명시된 조건에서만 NOT_APPLICABLE로 남습니다. [공통 오류 분류](../results.md#classification)도 확인하세요.

## 근거 읽기 {#evidence}

file_count와 가능한 경우 오류 path를 기록합니다. 파서는 호출 위치를 생성하지만 현재 판정에 전체 AST나 금지 노드 줄 목록을 저장하지 않습니다.

## 해결과 재검증 {#remedy}

1. 실패 파일을 찾아 문법 문제와 금지 동작을 구분합니다.
2. 파서 장애는 앱을 바꾸지 않고 환경을 먼저 복구합니다.
3. 전체 패치 검사를 다시 수행합니다. 문자열 난독화로 검사를 회피하는 것은 해결이 아닙니다.

[실패에서 다시 시작하는 방법](../troubleshooting.md#restart)을 참고하세요. 보존 자료 재검사는 원본 입력을 고치거나 새 소스를 가져오지 않습니다.

## 검증 사례 {#cases}

| 종류 | 입력 또는 상황 | 기대 결과 |
|---|---|---|
| 정상 | 주석 안의 eval( 문자열 | PASS |
| 위반 | eval 참조 또는 child_process require | BLOCK |
| 경계 | 지원 문법 밖의 새 JS 구문 | syntax BLOCK 가능; 악성 판정과 동일하지 않음 |
| 오류 | Node 파서 실행 실패 | ERROR |

위 표는 동작 설명입니다. 자동 재현한 범위와 테스트 연결은 아래 근거 및 [검증 사례집](../cases.md#reproduced)에서 구분합니다.

## 한계와 관련 검사 {#limits}

모든 JS 실행 능력이나 유출을 탐지하지 않습니다. 주석·일반 문자열은 AST의 실행 참조와 다르게 처리되지만 eval이라는 식별자 사용은 보수적으로 차단할 수 있습니다. G-002와 P-004가 별도의 강한 범위 제한을 제공합니다.
