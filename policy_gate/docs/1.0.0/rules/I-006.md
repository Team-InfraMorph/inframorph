# I-006 · 일반 설정과 비밀정보 분리

정책 1.0.0

## 목적 {#purpose}

일반 설정으로 비밀정보 이름이나 실행 환경을 덮어쓰는 것을 막습니다.

## 입력과 적용 조건 {#inputs}

Intent.config의 이름·문자열 값과 Intent.secrets의 이름 목록을 사용합니다. 비밀 값 자체는 입력으로 기대하지 않습니다.

## 처리 과정 {#procedure}

1. 일반 설정 이름과 비밀 이름의 교집합을 거부합니다.
2. SECRET/PASSWORD/TOKEN/API_KEY/DATABASE_URL 패턴 및 NODE_OPTIONS/NODE_PATH/LD_PRELOAD/PATH/HOME 이름을 거부합니다.
3. PORT, STORAGE_DRIVER, THUMB_SIZE 외 이름은 미지원입니다. 값은 각각 1~5자리 숫자, fs 또는 s3, 1~4자리 양수 형식을 요구합니다.

## 판정 기준과 사유 {#decisions}

| 사유 코드 | 현재 판정 | 발생 조건 | 확인과 조치 |
|---|---|---|---|
| config_overrides_secret | BLOCK | 일반·비밀 이름 충돌 | 비밀 참조는 secrets에 유지하고 config에서 제거합니다. |
| config_policy_violation | BLOCK | 금지 이름 또는 값 형식 오류 | 승인된 일반 설정만 생성하도록 분석/설계를 수정합니다. |
| config_not_supported | UNSUPPORTED | 지원 목록에 없는 설정 | 기능 필요성과 지원 추가를 검토합니다. |

위 조건을 모두 만족하면 해당 규칙 PASS입니다. 전체 배포 성공을 뜻하지 않습니다. 앞선 규칙에서 중단되면 NOT_RUN이며, 적용 제외는 명시된 조건에서만 NOT_APPLICABLE로 남습니다. [공통 오류 분류](../results.md#classification)도 확인하세요.

## 근거 읽기 {#evidence}

setting_names와 secret_count만 기록합니다. 오류 전에는 이 값이 아직 없을 수 있습니다. 설정·비밀의 실제 값은 근거에 넣지 않습니다.

## 해결과 재검증 {#remedy}

1. 이름 충돌·금지 이름·지원 밖 이름 중 어느 조건인지 확인합니다.
2. 앱의 실제 요구에 맞게 일반 설정과 비밀 이름을 분리합니다.
3. 분석 I-006뿐 아니라 설계 L-002의 같은 설정 검사도 확인합니다.

[실패에서 다시 시작하는 방법](../troubleshooting.md#restart)을 참고하세요. 보존 자료 재검사는 원본 입력을 고치거나 새 소스를 가져오지 않습니다.

## 검증 사례 {#cases}

| 종류 | 입력 또는 상황 | 기대 결과 |
|---|---|---|
| 정상 | PORT=3000 | PASS |
| 위반 | config에 DATABASE_URL | BLOCK |
| 경계 | PORT=99999 | I-006 단독 형식 통과; 설계/프로필에서 별도 제한 |
| 미지원 | CUSTOM=normal | UNSUPPORTED |

위 표는 동작 설명입니다. 자동 재현한 범위와 테스트 연결은 아래 근거 및 [검증 사례집](../cases.md#reproduced)에서 구분합니다.

## 한계와 관련 검사 {#limits}

PORT는 숫자 형식 검사이며 I-006만으로 유효 포트 범위를 보장하지 않습니다. Plan의 포트 스키마·L-002와 G-003의 3000 제한이 별도로 적용됩니다.
