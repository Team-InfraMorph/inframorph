# I-002 · worker 실행 근거

정책 1.0.0

## 목적 {#purpose}

worker의 진입점·명령·근거가 실제 소스와 연결되고 알려진 worker script가 누락되지 않았는지 확인합니다.

## 입력과 적용 조건 {#inputs}

Intent.workloads의 worker, package.json scripts, 진입 JS 파일과 인용. worker가 없어도 scripts.worker 누락 검사는 실행합니다.

## 처리 과정 {#procedure}

1. 명령을 셸 실행하지 않고 분리하여 node src/...js 두 인자인지 검사합니다. 경로 탈출은 거부합니다.
2. 진입 파일 존재를 확인합니다. 진입 파일의 비어 있지 않은 줄 또는 명령이 들어 있는 package.json 줄을 근거로 요구합니다.
3. package.json의 scripts.worker가 있다면 분석의 worker 명령 목록에 존재해야 합니다.

## 판정 기준과 사유 {#decisions}

| 사유 코드 | 현재 판정 | 발생 조건 | 확인과 조치 |
|---|---|---|---|
| worker_command_unsupported | UNSUPPORTED | 지원 node 명령 밖 | 지원 명령인지 검토합니다. 임의 셸을 허용하지 않습니다. |
| worker_entry_missing / worker_evidence_unrelated | BLOCK | 파일 없음 또는 근거 무관 | 실제 진입점과 실행 명령의 근거를 복원합니다. |
| worker_requirement_missing | BLOCK | scripts.worker가 분석에서 누락 | worker 요구를 재분석합니다. |
| package_invalid | BLOCK | JSON 파싱 실패 | 당시 package.json의 형식을 확인합니다. |

위 조건을 모두 만족하면 해당 규칙 PASS입니다. 전체 배포 성공을 뜻하지 않습니다. 앞선 규칙에서 중단되면 NOT_RUN이며, 적용 제외는 명시된 조건에서만 NOT_APPLICABLE로 남습니다. [공통 오류 분류](../results.md#classification)도 확인하세요.

## 근거 읽기 {#evidence}

분석에 포함된 worker 서비스 이름 services를 기록합니다. 실행 결과나 worker 산출물은 여기서 관측하지 않습니다.

## 해결과 재검증 {#remedy}

1. package scripts·진입 파일·분석의 명령을 함께 비교합니다.
2. 누락이면 분석을 수정하고 실제 명령 변경이면 새 소스로 검토합니다.
3. 새 Intent와 해당 Plan을 검사합니다. worker의 실제 처리 결과는 배포 검증에서 별도 확인합니다.

[실패에서 다시 시작하는 방법](../troubleshooting.md#restart)을 참고하세요. 보존 자료 재검사는 원본 입력을 고치거나 새 소스를 가져오지 않습니다.

## 검증 사례 {#cases}

| 종류 | 입력 또는 상황 | 기대 결과 |
|---|---|---|
| 정상 | node src/worker.js와 연결 근거 | PASS |
| 위반 | scripts.worker 존재·분석 worker 없음 | BLOCK |
| 경계 | worker도 scripts.worker도 없음 | PASS; worker 실행 검증 의미 아님 |
| 미지원 | npm run worker 또는 셸 명령 | UNSUPPORTED |

위 표는 동작 설명입니다. 자동 재현한 범위와 테스트 연결은 아래 근거 및 [검증 사례집](../cases.md#reproduced)에서 구분합니다.

## 한계와 관련 검사 {#limits}

임의 큐·스케줄러 자동 발견 기능이 아닙니다. scripts.worker라는 알려진 이름을 사용합니다. 예전 호환 진단의 I-005 표기는 현재 실행 규칙 ID I-002와 혼동하지 않아야 합니다.
