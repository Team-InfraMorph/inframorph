# 정책 변경 이력

## 1.0.0 {#policy-baseline}

검토된 demo-app Node 22 입력에 대한 정책 관리 기준입니다. 출시 태그·릴리스 기록을 자동으로 생성하지 않습니다.

| 영역 | 포함된 내용 | 확인할 설명 |
|---|---|---|
| 검사 | 지원 소스·Intent·설계·패치·빌드 입력의 18개 규칙, 실제 결과와 미실행 구분 | [규칙별 설명](rules/I-000.md#purpose) |
| 입력 계약 | Intent·Plan·manifest의 필수값·조건·실제 검증된 전체 예시 | [Plan 계약](rules/L-001.md#contract), [패치 계약](rules/P-001.md#contract) |
| 실패 처리 | 사유별 수정 안내, 실패→새 검사→원인 검토 연결 | [문제 해결](troubleshooting.md#reasons), [기록 예시](logs.md#walkthrough) |
| 배포 영향 | 보존 자료 재검사·검토·수동 재배포와 자료 부족의 구분 | [전환 안내](upgrade.md) |
| 문서 탐색 | 정책 버전별 목차·검색·고정 절·변경 이력 | [버전 관리](versioning.md#versions) |

## 설명과 관리 방식 정리 {#documentation}

문서도 정책 버전 1.0.0의 한 묶음으로 제공합니다. 입력 계약과 판정 기준은 유지하고, 설명·예시·사유 연결을 보완했습니다. 문서 선택과 링크는 정책 버전을 기준으로 하며 설명의 변경 차이는 Git에 남습니다.

과거 판정의 버전·입력·결과·문서 해시는 덮어쓰지 않습니다. 검사 결과에서 문서를 열면 해당 버전의 현재 설명이 열리고, 과거 설명의 정확한 내용은 저장된 해시와 Git 이력에서 확인합니다. 문서를 읽거나 버전을 선택하는 동작이 활성 정책을 변경하지는 않습니다.

## legacy 2.2.0 {#legacy}

관리 체계 도입 전 단계별 요약입니다. 정식 1.0.0의 이전 SemVer 릴리스가 아니며 새 규칙 결과로 재표기하지 않습니다. 존재하지 않는 과거 1.x 릴리스를 만들지 않습니다.
