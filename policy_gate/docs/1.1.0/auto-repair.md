# Policy 실패 후 AI 자동 수정

## 수정 대상 {#scope}

Intent의 분석 근거·요구사항 불일치, Plan의 분석 결과와의 불일치, 생성한 배포 패치의 문법·승인 변환 오류를 구분합니다. GitHub 원본 소스와 Policy 규칙은 수정하지 않습니다. 현재 지원 범위는 기존에 검토한 demo-app V1/V2입니다. 임의 앱의 비즈니스 로직을 자동으로 고치는 기능은 아닙니다.

## 횟수와 비용 {#limits}

Intent·Plan·코드 패치 전체가 배포 ID별 최대 3회를 공유합니다. 각 회차는 모델 호출 전에 SQLite에 예약합니다. 같은 응답·형식 오류·취소도 이미 사용한 회차를 돌려주지 않습니다. 프로세스 재시작과 다른 대상의 실행으로 제한이 초기화되지 않습니다. 모델은 현재 선택한 backend를 사용하며 API 기본값은 gpt-6-luna / low입니다.

각 회차는 모델 요청 1개로 제한하고, 기존 분석 비용과 앞선 수정 비용을 합쳐 기존 분석 예산 안에서만 요청합니다. 요청 크기·응답 크기·시간 제한을 유지합니다. 사용량을 확인할 수 없거나 응답이 불완전하면 멈춥니다. 반복된 Policy 차단과 형식 오류는 남은 회차 안에서만 다시 시도합니다.

## 재검사와 실행 {#validation}

AI는 수정 후보만 반환합니다. Intent는 원본 소스·근거·요구사항 검사를, Plan은 지원 프로필·Intent 관계 검사를 다시 통과해야 합니다. Plan 수정은 배포 승인 전에만 실행합니다. 저장된 롤백 계획과 분석 재사용(rebuild_only) 요청은 자동 수정하지 않습니다.

패치는 수정 가능한 파일 목록 안에서 새 배포 복사본으로 생성합니다. 호스트가 원본 대비 diff와 해시를 새로 계산하고 기존 Policy 전체를 실행합니다. 의존성 lockfile은 AI가 편집하지 않습니다. 통과한 패치만 Builder에 전달하며 빌드·Local health·데이터 읽기/쓰기 테스트를 통과해야 원격 배포로 진행합니다. Local에서 통과한 수정본은 AWS의 대상별 manifest로 다시 생성하고 같은 소스 해시인지 확인한 뒤 AWS Policy를 다시 실행합니다. 온프레미스는 기존 경로대로 Local 검증 이미지를 전달합니다.

Policy 수정 이후 Local 실행 테스트가 실패하면 자동 배포를 중단합니다. 기존 Local 실행 오류 재분석은 별도 1회 경로이며, Policy 자동 수정이 발생한 배포에서는 중복 실행하지 않습니다. AWS만 선택한 실행에서는 패치 자동 수정을 수행하지 않습니다. 코드 패치의 자동 수정·원격 전달에는 Local 테스트가 필요합니다.

## 자동 수정하지 않는 차단 {#stops}

미지원 원본 소스, 파일·manifest 변조, 경로/권한 위반, 시크릿, 금지 코드, 의존성 변경, 검사기 오류는 자동 수정 대상이 아닙니다. 모델이 이런 결과를 새로 만들면 즉시 중단합니다. DB 모델·데이터 삭제나 인프라 승인 우회는 허용하지 않습니다. 자동 수정 기능은 DB 준비·마이그레이션의 실행·재사용 조건을 변경하지 않습니다.

## 기록과 화면 {#history}

원래 BLOCK은 보존합니다. 정책 검사 화면의 AI 자동 수정 이력에서 회차·대상·차단 사유·수정 diff·재검사 결과·토큰 사용량을 확인합니다. diff는 마스킹 후 크기를 제한하며 원시 API 오류와 키를 저장하지 않습니다. 정책 재검사 통과는 배포 성공을 뜻하지 않습니다. 마지막 차단과 Local 실행 결과를 함께 확인해야 합니다.

## 재현 검증 {#tests}

tests/test_policy_auto_repair.py는 3번째 성공, 3회 소진, 단계 간 제한 공유, 재시작, 비용/사용량 제한, 실제 Gate를 통한 패치 복구·악성 결과 차단, Local 검증본의 AWS 전달을 확인합니다. scripts/verify_policy_auto_repair.py는 별도 테스트 상태에서 실행하며 기본 응답 재생과 명시적 OpenAI 모드를 구분합니다. 실제 AWS 리소스는 생성하지 않습니다.
