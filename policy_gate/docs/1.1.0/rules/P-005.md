# P-005 · 의존성 변경 범위

정책 1.0.0

## 목적 {#purpose}

저장 변환에 필요한 승인된 SDK 추가 이외의 패키지·스크립트·lock 변경을 제한합니다.

## 입력과 적용 조건 {#inputs}

package.json 또는 package-lock.json 변경 시 원본·결과, Plan.storage와 호스트 템플릿을 사용합니다.

## 처리 과정 {#procedure}

1. 패키지 관련 파일이 바뀌었다면 Plan.storage가 있어야 합니다.
2. package-lock.json은 호스트 승인 템플릿과 바이트 단위로 같아야 합니다.
3. package.json은 원본 JSON에 정확한 @aws-sdk/client-s3 버전을 추가한 결과와 같아야 합니다. 다른 키·스크립트·의존성 변경은 허용하지 않습니다.

## 판정 기준과 사유 {#decisions}

| 사유 코드 | 현재 판정 | 발생 조건 | 확인과 조치 |
|---|---|---|---|
| dependency_change_forbidden | BLOCK | 저장 변환 밖 패키지 변경·lock 불일치·JSON 오류 | 승인된 생성기와 SDK/lock 조합으로 재생성합니다. |

위 조건을 모두 만족하면 해당 규칙 PASS입니다. 전체 배포 성공을 뜻하지 않습니다. 앞선 규칙에서 중단되면 NOT_RUN이며, 적용 제외는 명시된 조건에서만 NOT_APPLICABLE로 남습니다. [공통 오류 분류](../results.md#classification)도 확인하세요.

## 근거 읽기 {#evidence}

패키지 관련 changed_paths를 기록합니다. CVE 검색 결과는 없습니다.

## 해결과 재검증 {#remedy}

1. 원본 package와 결과의 전체 JSON 차이를 확인합니다.
2. 앱의 의존성 업데이트는 앱 소스 변경으로 분리하고 지원 검토합니다.
3. 패치 검사를 통과한 뒤 X-001의 최종 의존성 고정 검사도 확인합니다.

[실패에서 다시 시작하는 방법](../troubleshooting.md#restart)을 참고하세요. 보존 자료 재검사는 원본 입력을 고치거나 새 소스를 가져오지 않습니다.

## 검증 사례 {#cases}

| 종류 | 입력 또는 상황 | 기대 결과 |
|---|---|---|
| 정상 | 승인 SDK 추가와 승인 lock | PASS |
| 위반 | scripts 또는 다른 dependency 추가 | BLOCK |
| 경계 | 관련 파일 미변경 | NOT_APPLICABLE |
| 오류 | JSON 파싱 오류 | 현재 dependency_change_forbidden BLOCK |

위 표는 동작 설명입니다. 자동 재현한 범위와 테스트 연결은 아래 근거 및 [검증 사례집](../cases.md#reproduced)에서 구분합니다.

## 한계와 관련 검사 {#limits}

취약점·라이선스·공급망 악성코드 스캐너가 아닙니다. 파일이 안 바뀌면 적용 제외이지만 최종 빌드 입력은 X-001이 다시 제한합니다.
