# P-004 · 허용된 코드 변환

정책 1.1.0

## 목적 {#purpose}

허용된 파일 안에 들어온 무관한 기능 변경을 막습니다. 경로와 해시가 맞는 것만으로 실행 동작을 승인하지 않습니다.

## 입력과 적용 조건 {#inputs}

변경 파일 목록, 원본·패치 JS의 정규화 AST, 승인된 storage 템플릿과 Plan.storage를 사용합니다. 앞선 P-001/P-006/P-007/P-002/P-003 이후입니다.

## 처리 과정 {#procedure}

1. 원본 변경 파일과 호스트 소유 템플릿을 JS 파서로 읽습니다. 원본 코드 자체를 실행하지 않습니다.
2. 원본과 변경 AST가 같으면 허용합니다. AST에서 위치·raw 표현은 제거하지만 지시문·정규식 등 의미 있는 구조는 유지합니다.
3. AST가 다르면 Plan.storage가 있고 승인 템플릿과 같은지 검사합니다. src/storage.js는 새 파일일 때, src/images.js는 검토된 원본 또는 이미 승인된 템플릿일 때 허용합니다.
4. 그 외 JS 변경은 차단합니다. corpus 전용 고정 변환은 호스트가 선택하는 테스트 프로필에만 있으며 일반 배포의 허용 범위가 아닙니다.

## 판정 기준과 사유 {#decisions}

| 사유 코드 | 현재 판정 | 발생 조건 | 확인과 조치 |
|---|---|---|---|
| patch_behavior_changed | BLOCK | 동일 AST도 승인 저장 변환도 아님 | 저장 변환과 무관한 변경을 제거하고 패치 생성기를 수정합니다. |
| javascript_parser_unavailable | ERROR | 원본·템플릿 파서 호출 실패 | 검사기 설치·실행 환경을 복구합니다. 보안 규칙을 완화하지 않습니다. |

위 조건을 모두 만족하면 해당 규칙 PASS입니다. 전체 배포 성공을 뜻하지 않습니다. 앞선 규칙에서 중단되면 NOT_RUN이며, 적용 제외는 명시된 조건에서만 NOT_APPLICABLE로 남습니다. [공통 오류 분류](../results.md#classification)도 확인하세요.

## 근거 읽기 {#evidence}

changed_paths를 기록합니다. 원본/결과 AST 전체나 어느 노드가 다른지는 결과에 저장하지 않습니다. 상세 차이는 패치 diff와 원본을 함께 확인해야 합니다.

## 해결과 재검증 {#remedy}

1. 코드 diff와 실제 Plan.storage를 확인합니다.
2. 앱 기능 변경은 원본 앱의 새 commit으로 분리하고 배포 패치는 승인된 변환 범위로 다시 생성합니다. 새 앱 소스가 지원 프로필 밖이면 별도 검토가 필요합니다.
3. P-001부터 패치 전체 검사를 다시 수행하고 빌드 직전 재검사도 확인합니다. manifest 해시만 다시 맞추는 것으로 해결되지 않습니다.

[실패에서 다시 시작하는 방법](../troubleshooting.md#restart)을 참고하세요. 보존 자료 재검사는 원본 입력을 고치거나 새 소스를 가져오지 않습니다.

실패 입력부터 해결 결과까지는 [수정·재검증 사례](../cases.md#patch-walkthrough)를 확인하세요.

## 검증 사례 {#cases}

| 종류 | 입력 또는 상황 | 기대 결과 |
|---|---|---|
| 정상 | 주석만 바꾸어 AST 동일 | PASS |
| 위반 | 허용 파일에 admin:true 추가 | BLOCK · patch_behavior_changed |
| 경계 | JS 변경 없음 | NOT_APPLICABLE · javascript_unchanged; 파서 호출은 수행 |
| 오류 | 원본/템플릿 파서 사용 불가 | ERROR; 의존성 검사 등 후속 중단 |

위 표는 동작 설명입니다. 자동 재현한 범위와 테스트 연결은 아래 근거 및 [검증 사례집](../cases.md#reproduced)에서 구분합니다.

## 한계와 관련 검사 {#limits}

범용 코드 동치성이나 업무 동작 보존을 증명하지 않습니다. JS 변경이 없으면 적용 제외이나 현재 구현은 그 분기에서도 템플릿 파싱을 수행하므로 파서 장애가 ERROR로 나타날 수 있습니다. 이 동작은 문서에서 숨기지 않고 보완 목록에 기록합니다.
