# P-007 · 소스 내 비밀정보

정책 1.0.0

## 목적 {#purpose}

패치 소스에 알려진 형태의 비밀정보가 포함된 채 빌드로 넘어가는 것을 막습니다.

## 입력과 적용 조건 {#inputs}

P-006을 통과한 패치 소스 파일의 전체 바이트. 실제 비밀 값의 유효성을 외부 서비스에 확인하지 않습니다.

## 처리 과정 {#procedure}

1. 각 파일에서 지원 private key 헤더를 검색합니다.
2. AKIA로 시작하는 20자리 접근키 형태와 gh[pousr]_ 접두사의 긴 토큰 형태를 검색합니다.
3. 첫 일치에서 secret_in_source로 종료합니다.

## 판정 기준과 사유 {#decisions}

| 사유 코드 | 현재 판정 | 발생 조건 | 확인과 조치 |
|---|---|---|---|
| secret_in_source | BLOCK | 알려진 비밀정보 패턴 일치 | 소스에서 제거하고 운영 비밀 주입으로 옮깁니다. 실제 유출이면 별도의 자격증명 폐기·교체 절차를 진행합니다. |

위 조건을 모두 만족하면 해당 규칙 PASS입니다. 전체 배포 성공을 뜻하지 않습니다. 앞선 규칙에서 중단되면 NOT_RUN이며, 적용 제외는 명시된 조건에서만 NOT_APPLICABLE로 남습니다. [공통 오류 분류](../results.md#classification)도 확인하세요.

## 근거 읽기 {#evidence}

검사 파일 수만 남깁니다. 원문 비밀과 매치 위치는 결과에 저장하지 않으므로 문서가 어느 파일의 값인지 단정하지 않습니다.

## 해결과 재검증 {#remedy}

1. 민감정보를 로그에 복사하지 않고 비공개 소스에서 확인합니다.
2. 실제 값인지 예제인지 검토하고 안전한 예제로 변경하거나 비밀 주입 경로를 사용합니다.
3. 전체 패치 검사와 새 빌드 입력을 확인합니다. 기존 노출 기록은 삭제로 은폐하지 않습니다.

[실패에서 다시 시작하는 방법](../troubleshooting.md#restart)을 참고하세요. 보존 자료 재검사는 원본 입력을 고치거나 새 소스를 가져오지 않습니다.

## 검증 사례 {#cases}

| 종류 | 입력 또는 상황 | 기대 결과 |
|---|---|---|
| 정상 | 소스에는 비밀 이름만 있고 값은 없음 | PASS |
| 위반 | 테스트용으로 조합한 알려진 토큰 형태 | BLOCK |
| 경계 | 알려진 접두사가 없는 일반 문자열 | 탐지 보장 없음 |
| 오류 | 읽기 실패 | 앞선 P-001에서 처리; 이 규칙 NOT_RUN |

위 표는 동작 설명입니다. 자동 재현한 범위와 테스트 연결은 아래 근거 및 [검증 사례집](../cases.md#reproduced)에서 구분합니다.

## 한계와 관련 검사 {#limits}
