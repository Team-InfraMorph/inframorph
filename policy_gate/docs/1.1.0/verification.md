# 정책 1.1.0 검증 기록 읽기

## 실행 결과의 기준 {#results}

1.1.0은 I-003·I-002의 직접 근거와 제한된 AI 수정·변경 영향 연결을 검증합니다. 1.0.0에서 확인한 테스트 수를 1.1.0의 실행 결과로 재사용하지 않습니다. 실제 실행 명령·통과 수·미실행 항목은 이 변경의 PR 검증 기록과 별도 생성한 예시 결과에서 확인합니다.

| 검증 | 확인하는 내용 | 결과를 읽는 기준 |
|---|---|---|
| 근거 규칙 회귀 | provider 토큰·worker 명령과 시작점·미실행·파서 경계 | 실제 검사 결과. 파서 단위 변형을 일반 소스 지원으로 해석하지 않음 |
| AI 수정 회귀 | 최초 입력의 수정 범위·공유 회차·실패·재검사 | 응답 재생과 실제 모델 호출을 구분 |
| 변경·배포 영향 회귀 | 이전 정책·동일 버전 다른 식별값·자료 부족·비대상 | 과거 PASS와 현재 판정을 각각 유지 |
| UI 검사 | 이전·새 조건·직접 근거·수정 종료·예시 표기 | 서비스 실행이나 보안 정확도의 증거 아님 |
| 이전 정책 비교 | 고정 1.0.0 commit의 별도 검사기 결과 | 과거 검사기의 commit·입력·정책 식별값으로 확인 |

고정 redteam corpus의 revision은 validation/redteam-source.json을 기준으로 합니다. corpus 사례 통과를 범용 앱의 공격 차단 확률이나 배포 성공률로 표현하지 않습니다.

## 확인 범위 {#findings}

강화된 규칙은 지원 원본의 인용만 부족한 분석을 제한합니다. 원본 소스와 요구를 제한하는 G-002는 유지합니다. 따라서 기존 사례의 통과는 악성 앱 실행 우회였다는 주장이 아닙니다.

1.0.0 문서와 기준선·과거 판정은 유지합니다. 1.1.0의 구현 변경은 정책 식별값과 규칙 정의 2에 반영됩니다. 과거 1.1.0 기록도 같은 숫자만으로 현재 조건과 같다고 보지 않습니다.

## 화면 확인 {#ui}

버전 비교에서 이전·새 조건, 적용 대상, 필요한 조치를 먼저 확인합니다. 배포 영향의 운영 기록과 검증 예시는 분리합니다. 예시는 서비스 실행 미확인과 AI 호출 방식을 표시하고 운영 작업 버튼을 제공하지 않습니다.

검사 상세에서는 제출 인용·필요 위치·부족한 역할을 읽습니다. AI 이력에서는 원래 정책 실패와 모델 종료 사유, 수정 범위·diff·재검사 연결을 구분합니다. 과거 기록의 없는 필드는 미보존입니다.

## 검증의 한계 {#limits}

실제 AI 호출은 자격 증명과 기존 비용 제한 아래 별도로 수행하고, 미수행이면 그대로 미실행으로 기록합니다. 모의 응답은 실패를 결정적으로 재현하기 위한 자료입니다. 이번 정책 검증은 신규 Docker·AWS·온프레미스 배포나 휴대전화 공개 접속을 증명하지 않습니다.
