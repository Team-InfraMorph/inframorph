# 정책 버전 관리

## 정책과 문서는 같은 버전을 사용합니다 {#versions}

정책 1.1.0을 선택하면 해당 버전의 규칙·지원 범위·실행 흐름·문제 해결 안내를 함께 조회합니다. 문서마다 별도 번호를 선택하지 않습니다. 1.1.0의 설명은 policy_gate/docs/1.1.0에 한 묶음으로 관리합니다.

| 기준 | 역할 |
|---|---|
| 정책 버전 | 사용자가 선택하는 규칙과 문서의 기준. 현재 1.1.0 |
| Git commit·PR | 설명·구현의 변경 내용과 검토 이력 |
| 정책·구현 해시 | 특정 실행이 사용한 정책 묶음과 검사기 파일의 식별값 |
| 문서 해시 | 설명의 정확한 내용 식별값. 버전 선택기를 늘리는 값이 아님 |

문서 화면에서 버전을 선택해도 활성 정책은 바뀌지 않습니다. 실제 실행 정책은 서버가 사용하는 검토된 설정과 코드로 정합니다.

## 변경을 판단하는 기준 {#behavior-change}

문서화한 계약의 실행 오류 수정은 PATCH, 기존 계약을 유지한 선택 기능은 MINOR, 기존 지원 입력의 새로운 차단 조건·지원 제거는 MAJOR 원칙으로 검토합니다. 보안 오류를 고친 PATCH도 재검사가 필요할 수 있으므로 숫자만으로 조치를 결정하지 않습니다. 실제 조건 변경을 단순 설명 정정으로 처리해서는 안 됩니다.

현재 상태·재현 사례·조건 차이·영향 대상·필요한 재검사 및 검토·회귀 근거를 함께 확인합니다. 설명만 바꿨는지 여부는 실제 구현과 대조하며, Git 이력과 변경 이유를 기록합니다.

## 과거 기록과 정확한 설명 {#history}

원래 검사 기록은 수정하지 않습니다. 각 검사에 저장된 정책 버전·정책 해시·문서 해시로 당시 근거를 대조합니다. 문서 화면의 링크는 해당 정책 버전의 설명으로 이동합니다. 설명 정정 전의 정확한 내용이 필요하면 Git의 해당 문서 변경 이력과 저장된 내용 해시를 확인합니다.

출시된 정책 묶음을 덮어쓰지 않는 검사는 유지합니다. 원격 출시·태그 생성과 로컬 기준선 검증은 구분합니다.

## 기준선 검사의 범위 {#baseline}

| 보호 장치 | 실제 확인 범위 | 한계 |
|---|---|---|
| Git commit | 포함된 저장소 파일의 이력·차이 | commit 자체가 테스트 성공이나 변경 승인 증거는 아님 |
| 정책 구현 식별값 | catalog의 IMPLEMENTATION 목록, schemas·code_patch/templates 아래 .py/.js/.json | 모든 실행 파일을 자동 포함하지 않음 |
| 정책·규칙 식별값 | 규칙 카탈로그·manifest와 위 구현 식별값 | 실제 배포 결과나 서비스 가용성을 입증하지 않음 |
| 문서 기준선 | policy_gate/docs/1.0.0 전체 파일의 목록·바이트 해시 | Git 기준 없이 검사하면 기준선 파일 자체의 과거 내용은 비교하지 않음 |
| 회귀 검사 | 규칙과 문서 연결, 실제 입력 예시, 기록 재현, 문서 변경과 판정 식별값의 분리 | 문장 의미나 모든 호출 경로가 자동 검증되는 것은 아님 |

보존하는 기준선 파일은 policy_gate/baselines/1.0.0.json입니다. 정책·규칙·구현 식별값과 문서 목록·해시를 대조하며, Git 비교 기준이 있으면 기준선 파일 자체의 수정·삭제도 검사합니다.

현재 구현 해시에는 Gate·규칙·기록·정책 API·Local/AWS Adapter·Builder 등의 명시된 파일이 포함됩니다. control_plane/runtime.py, control_plane/auto_repair.py, code_patch/runner.py도 포함합니다. control_plane/orchestrator.py와 control_plane/onprem_deploy.py는 그 목록과 추가 폴더 범위에 없습니다. 이 파일의 변경은 Git 차이와 실행 회귀도 함께 확인합니다. 전체 배포 제어 흐름이 같은 해시 아래 불변이라는 보장은 아닙니다. 저장소 검증을 외부 감사 시스템 수준의 위변조 방지 보장으로 해석하지 않습니다.

## 1.1.0 구현 범위 {#repair-identity}

1.0.0 기준선과 설명은 보존합니다. 1.1.0은 개발 중인 자동 수정 확장으로, 기존 18개 검사 규칙을 변경하지 않습니다. 자동 수정 구현·분석 경로·패치 생성기도 구현 식별값에 포함합니다. 1.1.0 기준선은 아직 고정하지 않았습니다.
