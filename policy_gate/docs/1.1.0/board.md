# 체험 보드 지원 계약

## 범위 {#scope}

체험 V1(board-v1)은 web·SQLite 분석·uploads 파일 저장 요구를 갖습니다. 체험 V2(board-v2)는 동일 API·DB 스키마에 `node src/worker.js` 집계를 추가합니다. 두 버전은 Local 전용입니다. 기존 V1·V2의 Local/AWS 프로필은 유지합니다.

## 파일과 근거 {#files}

G-002는 호스트의 analyzer/board-profiles.json에 등록한 전체 commit과 소스 파일 목록·SHA-256을 비교합니다. 서버, Prisma, package/lock, 화면, 기본 이미지가 모두 일치해야 합니다. 누락·추가·변조·두 버전의 파일 혼합은 unreviewed_runtime_source로 차단합니다. 임의 commit이나 같은 화면의 수정본은 자동 승인하지 않습니다.

화면이나 그림을 빌드 입력으로 허용한다는 뜻은 분석 근거로 인정한다는 뜻이 아닙니다. Intent의 workload/state 근거는 서버·Prisma·images·worker·package의 실제 코드 줄이어야 합니다. src/web의 캡션, JSON 이미지, 화면 문구는 non_source_evidence로 거부합니다.

G-003은 등록된 체험 commit의 대상이 Local인지 확인합니다. 버전 선택 UI와 요청 검증에서도 Local 외 대상을 작업 생성 전에 거부합니다. 직접 요청이나 브랜치 HEAD도 정책 검사를 통과해야 합니다.

## 패치와 실행 {#execution}

화면과 이미지 파일은 패처가 변경하지 않습니다. 기존 P 규칙은 원본과 최종 전체 입력의 해시 및 허용 변환을 비교합니다. Builder의 COPY src가 검사한 자료를 포함합니다. 실행 검사는 각 화면·이미지 응답을 등록 해시와 비교합니다.

체험 V2에만 강화된 worker 실행 확인을 적용합니다. 현재 컨테이너의 실행 상태와 이미지 ID를 확인하고, 메모를 생성한 시각 이후 현재 컨테이너에서 발생한 구조화된 note_count 이벤트를 최대 30초 동안 확인합니다. 집계값은 생성 후 서버에서 조회한 메모 수 이상이어야 합니다. 과거 로그·임의 문장·재시작된 컨테이너는 성공 근거로 사용하지 않습니다.

worker 실행 실패는 실행 검사 실패이며 정책 위반이 아닙니다. 기존 서비스가 있으면 Local 복구를 시도하고 복구 결과를 별도로 기록합니다. 앱의 ‘worker 포함’ 배지는 구성 안내일 뿐 정상 동작의 증거가 아닙니다.

## 한계와 조치 {#limits}

등록된 두 파일 묶음만 지원하며 일반 웹앱 지원으로 확대하지 않습니다. 그림은 요구사항의 근거가 아닙니다. 집계 확인은 해당 실행 시점의 확인이며 지속 모니터링이 아닙니다. 공개 주소와 폰 확인도 정책 PASS와 별도입니다.

수정본은 새로운 소스 검토·commit 등록이 필요합니다. 이미지 내용은 PNG/JPEG 원본을 Base64 JSON으로 보관하며 개별 JSON은 220KiB 이하입니다. 업로드 API의 기존 5MB 계약·응답·DB 스키마는 유지합니다.
